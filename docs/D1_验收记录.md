## 两个设计要点

### 1. 为什么 `Device` 的析构必须 `virtual`

```cpp
Device *p = new TcpDevice;   // 静态类型 Device，动态类型 TcpDevice
delete p;                    // 通过基类指针释放
```

如果 `~Device()` 不是虚函数，`delete` 只按**静态类型**调用 `~Device()`，`TcpDevice` 自己那部分资源（socket、缓冲、成员对象）不会被释放，造成泄漏，行为未定义。加了 `virtual` 后通过虚表找到 `~TcpDevice()`，先析构派生部分再析构基类部分。

结论：**只要一个类打算被继承、且可能被基类指针 delete，析构函数就得是 virtual**。Qt 里 `QObject` 的析构本来就是虚的，所以继承 QObject 天然满足；但写纯 C++ 接口时必须自己加。

### 2. `AUTOMOC` 解决什么

`Q_OBJECT` 宏声明了 signals / slots / 属性，但普通 C++ 编译器不认识它。Qt 的 **moc**（元对象编译器）会先扫描含 `Q_OBJECT` 的头文件，生成 `moc_xxx.cpp`（信号的函数体、元对象表、qt_metacall 等），再一起编译链接。`CMAKE_AUTOMOC ON` 就是让 CMake 自动找出这些头文件、调用 moc、把生成文件加进目标，不用手写。

少了它的典型报错：`undefined reference to vtable for Device` 或 `undefined reference to Device::sigStateChanged(...)`。同类工具还有：**uic**（`.ui` → `ui_xxx.h`）、**rcc**（`.qrc` → `qrc_xxx.cpp`），都是「先生成 C++ 再编译」。
